# spiffe-issuer

Tool-tier standalone app: mints three test JWT-SVIDs (valid, mismatched, untrusted), publishes the JWKS + OIDC discovery a Privilege gateway can fetch, and presents each token to an MCP door (`initialize` + `tools/list`). It is a token minter, NOT SPIRE; say so wherever it shows tokens.

- Run: `./scripts/run.sh` (http://127.0.0.1:7828). Test: `npm test` (server = `node --test test/*.test.js`, web = vitest, `scripts/*.test.mjs`). Preflight: `npm run doctor`. Outside check of a running lab: `node scripts/verify-live.mjs`.
- Core: `server/src/keys.js` (two keys, persisted in DATA_DIR mode 600; RS256 default, ES256 via createECDH), `svid.js` (mint three tokens, `verify`), `config.js` (settings: lab `.env`/env over the shared file, only `SPIFFE_*` and `PUBLIC_URL`), `present.js` (Real via the vendored hop `gatewayReal.js`; Mock rehearsal), `app.js` (public `/.well-known/*`, local `/api/*`), `safety.js`, `netguard.js`.
- Rules that bite:
  - The private keys never leave `keys.js`: no route, trace, log or test output carries them (a test scans every response). The untrusted key is never published.
  - `/.well-known/jwks.json` and `/openid-configuration` answer for ANY Host (the gateway fetches them through a tunnel); everything else keeps the loopback/`LAB_ALLOWED_HOSTS` check, and `/api` refuses requests carrying tunnel/proxy headers. The API can mint tokens a gateway trusts: it must never be reachable from the internet.
  - Real mode may reach exactly the configured gateway origin, only while presenting (netguard). Mock makes zero outbound calls. Real is the start mode when configured (rule 26); never remove the Mock/Real toggle (rule 26).
  - Mock rows are labelled MOCK and use `.invalid` hosts; a real trace never says `checked` (`assertTrace`); no full token in any trace.
  - Lifetime is capped at 300 s (`MAX_LIFETIME_SEC`). One port, 7828, loopback publish. Only `.example` / `.invalid` hosts in files and tests; tests set `STANDALONE_ENV` to a missing file so the real shared file is never read.
  - Vendored byte for byte and pinned, never edited: `server/src/gatewayReal.js` (shared/gateway-real), `server/src/gatewayTrace.js` + `web/src/gateway-trace/*`, `web/src/components/JsonPane.*`, `web/src/top-menu/*`, `web/src/standalone-ui.css`, `web/src/story/` + `server/src/story/` + `scripts/story-checkPin.mjs` (shared/story in AI-DEMO-Standalone at 605e3b7; `node scripts/story-checkPin.mjs .` checks the pin; the wording is `video/captions.md`, served at `GET /api/story` by `server/src/storyRoute.js`). Re-vendor with `cp`, then re-pin (`scripts/repo.test.mjs` checks every pin). Never use `crypto.generateKeyPair('ec')`.
- Run observability (rule 27): the panel is vendored byte for byte and pinned (`web/src/run-observability/`, `server/src/runObservability.js`, `scripts/run-observability-checkPin.mjs`); never edit it, change the canonical in AI-DEMO-Standalone first. This lab vendors the CORE only: it reads no product log, so no `runObservabilityReaders.js`, no `RUN_OBS_*` variable and no Docker socket (a test asserts no server file names a log reader). The lab's half is `server/src/runLog.js`: one stdout line per decision (`result=passed|stopped|unclear|no-reply`; never the words refused, denied, rejected, forbidden, failed, invalid, expired, mismatch, token, audience, scope, served; every value cut to `A-Za-z0-9._:/@-`) and a list of present runs that `GET /api/run-observability` turns into a record for the current mode: Mock rows `simulated` (the lab's own verification), Real rows `response` (the gateway's reply), never `logged`. Only the Agent gateway layer has rows; the other five say why they have none.
- Honesty: a JWT-SVID from a REAL SPIRE (1.7.2 on Kubernetes) was accepted by a real Privilege gateway door on 2026-11-19 (200 for the registered ID; 401 for another ID, a wrong audience, a tampered signature and no token). On 2026-11-22 this lab's OWN tokens (RS256, `aud` as one string) got 200 / 401 / 401 (Valid / Mismatched / Untrusted) from a real gateway door in Real mode, with a recorded take under `video/`. The gateway logs no per-call line for them, so a 401's reason is inferred from the one difference, never claimed as read from the gateway. Claim no more than that.
- SPIRE card (`spireControl.js`, `spireGuide.js`, `SpireCard.jsx`, `scripts/verify-svid.mjs`): the local demo needs Docker and the exact container/image in `spireControl.js` (config lists for `ca_subject`, health on 8080, probe `/ready`, never a bare TCP port). The card has a Docker / Cluster target switch (`spireControl.js` `setTarget`, `/api/spire/target`; runtime state, Cluster refuses with 409 without a valid URL; Start/Restart only ever drive Docker, the cluster gets placeholder kubectl commands, never credentials). `SPIRE_SERVER_URL` allows a path prefix; an invalid one is `mode: invalid`, never the local mode. The remote test reaches only the configured origins (`setAllowedOrigins`), only per button press, no redirect, and fails on private key material in a published key set. The guide names no one's host, tenant or audience (a test scans it).
